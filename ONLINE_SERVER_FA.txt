راهنمای راه‌اندازی بازی آنلاین Mind Bastion (سرور داخل ایران)
==========================================================

وضعیت فعلی
----------
کد صف انتظار و سرور WebSocket در پوشه online-server آماده است، اما تا وقتی این سرویس را در حساب میزبانی خودتان deploy نکنید و نشانی واقعی آن را در project.godot نگذارید، دکمه «جستجوی هم‌بازی آنلاین» به سرور واقعی وصل نخواهد شد. بدون دسترسی به حساب Liara شما نمی‌توانم آن را مستقیماً از این محیط منتشر کنم.

پیشنهاد میزبانی
---------------
برای میزبانی داخل ایران از یک برنامه Node.js روی Liara استفاده کنید. مستندات رسمی Liara استقرار برنامه‌های Node.js و فایل liara.json را توضیح می‌دهد:
https://github.com/liara-cloud/docs/blob/master/src/pages/paas/nodejs/how-tos/deploy-app.mdx
ساخت برنامه Node.js و دامنه پیش‌فرض نیز در این راهنمای رسمی آمده است:
https://github.com/liara-cloud/docs/blob/master/src/pages/paas/nodejs/how-tos/create-app.mdx

انتخاب زیرساخت داخل ایران وابستگی به سرویس خارجی را کم می‌کند، اما نمی‌توان تضمین کرد دسترسی در همه‌ی اپراتورها/ISPها و در همه‌ی زمان‌ها بدون اختلال یا فیلتر باشد. پس از انتشار، اتصال را با اینترنت همراه و Wi-Fi جداگانه آزمایش کنید.

۱) ساخت برنامه در Liara
----------------------
1. وارد https://console.liara.ir شوید یا از https://liara.ir وارد پنل شوید.
2. یک برنامه جدید با پلتفرم NodeJS بسازید؛ اگر پنل محل استقرار را می‌پرسد، منطقه/دیتاسنتر ایران را انتخاب کنید.
3. برای شناسه برنامه یک نام یکتا انتخاب کنید؛ نمونه: mind-bastion-matchmaker-123. شناسه واقعی خودتان را یادداشت کنید.

۲) روش ساده‌تر: انتشار خودکار با GitHub Actions
-----------------------------------------------
در مخزن GitHub پروژه وارد Settings → Secrets and variables → Actions شوید و این دو مقدار را تعریف کنید:

- Repository variable با نام LIARA_MATCHMAKER_APP و مقدار شناسه‌ی برنامه Node.js که در Liara ساخته‌اید.
- Repository secret با نام LIARA_API_TOKEN و مقدار توکن API لیارا.

سپس در GitHub Actions، workflow با نام Deploy Online Matchmaker to Liara را باز و Run workflow را اجرا کنید. این workflow ابتدا ۶ تست پروتکل را اجرا می‌کند و سپس فقط پوشه online-server را روی برنامه Liara منتشر می‌کند. بعد از راه‌اندازی اولیه، تغییرات پوشه online-server نیز باعث deploy خودکار می‌شوند.

روش جایگزین: انتشار از کامپیوتر
------------------------------
Node.js را روی کامپیوتر نصب کنید، سپس در PowerShell یا ترمینال اجرا کنید:

  npm install -g @liara/cli
  liara login

به پوشه online-server در همین پروژه بروید. مثال در ویندوز (مسیر را با مسیر واقعی خودتان عوض کنید):

  cd C:\path\to\MindBastion_Modular\online-server
  liara deploy --app YOUR_LIARA_APP_ID

به‌جای YOUR_LIARA_APP_ID شناسه‌ی برنامه‌ای را قرار دهید که در مرحله‌ی اول ساختید. فایل liara.json در این پوشه پورت 3000 و Node.js 22 را تنظیم می‌کند.

۳) آزمایش سرویس
----------------
اگر شناسه‌ی برنامه شما مثلا mind-bastion-matchmaker-123 باشد، نشانی سلامت باید شبیه این باشد:

  https://mind-bastion-matchmaker-123.liara.run/health

پاسخ باید یک JSON با ok=true و service=mind-bastion-matchmaker باشد. اگر خطای 404 یا خطای سرویس دریافت کردید، لاگ استقرار را در پنل Liara بررسی کنید.

۴) اتصال نسخه وب به سرور
-----------------------
فایل project.godot را باز کنید و بخش network را پیدا کنید. مقدار matchmaking_url فعلی نمونه است و باید با دامنه واقعی شما جایگزین شود. مثال:

  [network]
  matchmaking_url="wss://mind-bastion-matchmaker-123.liara.run/ws"

نام نمونه را با نام واقعی برنامه خودتان عوض کنید. برای سایت GitHub Pages با دامنه tornastore.github.io، مقدار پیش‌فرض سرور، Origin همین سایت را مجاز می‌کند. اگر سایت را با دامنه‌ی دیگری هم اجرا می‌کنید، متغیر محیطی ALLOWED_ORIGINS را در Liara تنظیم کنید و Origin دقیق سایت‌ها را با کاما جدا کنید.

سپس در ریشه‌ی مخزن اجرا کنید:

  git add project.godot main.gd online-server ONLINE_SERVER_FA.txt
  git commit -m "Configure online matchmaking server"
  git push origin main

پس از سبزشدن GitHub Actions، صفحه‌ی بازی را با Ctrl+F5 تازه‌سازی کنید. دو کاربر باید در صفحه‌ی بازی آنلاین، یک بازی یکسان را انتخاب کنند؛ اولین کاربر در صف می‌ماند تا بازیکن بعدی همان بازی پیدا شود. نام کاربری و ایموجی‌های مجاز به حریف نمایش داده می‌شوند.

نکات مهم
--------
- اتصال مستقیم ENet/IP در APK/Desktop حفظ شده است؛ matchmaking با WSS راه جداگانه‌ای دارد.
- در مرورگر IP و UDP مستقیم استفاده نمی‌شود؛ همه‌ی ارتباطات نسخه وب از این سرور عبور می‌کند.
- اتاق‌ها در حافظه نگهداری می‌شوند؛ restart سرور بازی‌های جاری را قطع می‌کند.
- سرور، صف و رله حرکت‌ها را مدیریت می‌کند؛ هنوز داور کامل سمت سرور برای جلوگیری از کلاینت دستکاری‌شده نیست. برای بازی دوستانه مناسب است، اما برای مسابقه‌ی دارای رتبه/جایزه به اعتبارسنجی قواعد سمت سرور نیاز است.
- نام کاربری فقط نام نمایشی است؛ حساب امن/رمز عبور و ذخیره‌ی رتبه‌بندی آنلاین در این نسخه وجود ندارد.
