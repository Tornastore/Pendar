# Mind Bastion — مجموعه بازی‌های فکری

## اتصال چندنفره (وای‌فای محلی)

### مراحل اتصال دو گوشی

1. **هر دو گوشی به یک وای‌فای** وصل باشند (هات‌اسپات یکی هم OK است).
2. روی گوشی اول: بازی را انتخاب کنید → **میزبانی روی وای‌فای**.
   - IP گوشی میزبان در صفحه لابی نمایش داده می‌شود (مثلاً `192.168.1.12`).
3. روی گوشی دوم: همان بازی را انتخاب کنید → **اتصال با IP**.
   - IP میزبان را وارد کنید و اتصال را بزنید.
4. وقتی لابی میزبان دو بازیکن را نشان داد، میزبان دکمه **شروع بازی** را می‌زند.
5. هر نفر فقط در نوبت خودش می‌تواند حرکت کند. در فکر بکر، میزبان کد مخفی را نگه می‌دارد و مهمان حدس می‌زند.

### نکات مهم
- فایروال/دیتای موبایل را خاموش کنید؛ فقط وای‌فای.
- اگر IP نشان داده نشد، از تنظیمات وای‌فای گوشی Host آن را پیدا کنید.
- پورت: `7777/UDP` (ENet).
- این اتصال IP در خروجی بومی Android/Desktop کار می‌کند. در نسخه وب، اتصال آنلاین از طریق صف انتظار و WebSocket امن انجام می‌شود؛ راه‌اندازی سرور آن در `ONLINE_SERVER_FA.txt` توضیح داده شده است.
- بلاک‌آس و فکر بکر هر دو در فهرست بازی‌های اصلی قرار دارند و حالت شبکه‌ای دو گوشی دارند؛ در فکر بکر، کد مخفی به دستگاه مهمان ارسال نمی‌شود.
- کوریدور علاوه بر بازی با کامپیوتر، حالت چهار نفره محلی روی یک دستگاه دارد؛ اتصال شبکه‌ای کوریدور فعلاً فعال نیست.

## نسخه ۱۲ — بازطراحی رابط کاربری
- تم تیره مدرن، کارت‌ها و دکمه‌های گرد با سایه، آیکون‌های برداری، انیمیشن مهره‌ها

- برای فونت فارسی بهتر: فایل‌های Vazirmatn-Regular.ttf و Vazirmatn-Bold.ttf را در پوشه fonts/ بگذارید (خودکار شناسایی می‌شود)

## معماری ماژولار

ساختار تفکیک‌شده و راهنمای ادامه توسعه در `ARCHITECTURE.md` قرار دارد. منطق و state بازی‌ها در `games/<game_id>/rules.gd`، کاتالوگ در `core/game_catalog.gd` و امتیازدهی/رتبه‌بندی در `services/` قرار گرفته‌اند. برای کنترل ساختاری سریع، از ریشه پروژه دستور `python tools/verify_structure.py` را اجرا کنید.

## خروجی وب و انتشار روی GitHub Pages
- با هر push به شاخه `main`، workflow با نام **Deploy Web App to GitHub Pages** به‌طور خودکار خروجی وب را می‌سازد و منتشر می‌کند؛ اجرای دستی از **Actions → Deploy Web App to GitHub Pages → Run workflow** هم پشتیبانی می‌شود.
- قبل از اولین انتشار، در **Settings → Pages → Build and deployment**، گزینه **Source** را روی **GitHub Actions** بگذارید.
- برای ساخت فایل وب بدون انتشار، از **Actions → Build Web App (artifact only) → Run workflow** استفاده کنید و artifact با نام `MindBastion-Web` را دانلود کنید.
- برای خروجی Android، از **Actions → Build Android APK → Run workflow** استفاده کنید؛ این workflow دیگر با هر push وب هم‌زمان اجرا نمی‌شود.
- خروجی وب با PWA تنظیم شده و در مرورگرهای پشتیبانی‌شده امکان نصب روی صفحه اصلی و کش آفلاین دارد. برای اجرای محلی، فایل‌ها را از طریق وب‌سرور باز کنید (مثلاً `python -m http.server 8000` در پوشه خروجی)؛ بازکردن مستقیم `index.html` با `file://` قابل اتکا نیست.
- **شبکه وب:** مرورگر از ENet/UDP مستقیم پشتیبانی نمی‌کند؛ نسخه وب از WebSocket امن و صف انتظار استفاده می‌کند. سرور Node.js در `online-server/` قرار دارد و برای راه‌اندازی در ایران، راهنمای `ONLINE_SERVER_FA.txt` را ببینید. ابتدا برنامه Liara را بسازید، GitHub Actions variables/secrets را تنظیم کنید و URL واقعی WSS را در `project.godot` قرار دهید؛ قبل از این کار matchmaking آنلاین هنوز به سرور متصل نیست.
- آمار و رتبه‌بندی محلی در مرورگر به مجوز ذخیره‌سازی مرورگر وابسته است؛ در حالت ناشناس یا با مسدودکردن IndexedDB ممکن است ماندگار نباشد.

### هوش مصنوعی شش‌سطحی

هوش اتلو، کوریدور، شطرنج، تخته‌نرد، پنتاگو، دومینو، بلاک‌آس و فکر بکر از طریق ماژول‌های مستقل هر بازی پیاده‌سازی می‌شود. شطرنج از ارزیابی موقعیت و جست‌وجوی آلفا–بتا استفاده می‌کند؛ تخته‌نرد توالی تاس‌های نوبت را ارزیابی می‌کند؛ پنتاگو تهدیدهای پنج‌تایی و برد فوری حریف را می‌سنجد؛ و دومینو میزان انعطاف دست، سرهای زنجیر و ادامه‌های احتمالی را ارزیابی می‌کند. سطح هوش از صفحهٔ انتخاب حالت بازی قابل تنظیم است؛ در پنتاگو و دومینو سطح انتخاب‌شده داخل صفحهٔ بازی هم با نشان «هوش CPU» نمایش داده می‌شود. برای اعمال این تغییر در سایت، فایل‌های `main.gd`، `games/pentago/rules.gd` و `games/domino/rules.gd` باید به شاخهٔ `main` ارسال و سپس Workflow انتشار موفق شود. قوانین شطرنج و تخته‌نرد در این نسخه همچنان مدل ساده‌شدهٔ فعلی پروژه هستند؛ جزئیات در README هر بازی آمده است.


## راه‌اندازی بازی آنلاین وب
- صف انتظار کاربران را بر اساس شناسه‌ی بازی جفت می‌کند؛ نام نمایشی و هشت ایموجی رایج پشتیبانی می‌شوند. راه‌اندازی سرور Node.js در پوشه‌ی `online-server/` و مراحل کامل استقرار در ایران در `ONLINE_SERVER_FA.txt` است.
- برای Deploy خودکار سرور، شناسه برنامه Liara را به‌عنوان Repository variable با نام `LIARA_MATCHMAKER_APP` و API token را در Repository secret با نام `LIARA_API_TOKEN` ثبت کنید. سپس Workflow با نام `Deploy Online Matchmaker to Liara` را اجرا کنید.
- پس از انتشار سرور، مقدار `network/matchmaking_url` در `project.godot` را با `wss://YOUR_APP_ID.liara.run/ws` جایگزین کنید و Push کنید تا نسخه‌ی وب دوباره build شود.

## بازنگری هوش مصنوعی — سطح استاد و استادتمام
- شطرنج: جست‌وجوی آلفا-بتا با مرتب‌سازی حرکت، جدول موقعیت‌های تکراری، و جست‌وجوی تاکتیکی در انتهای شاخه‌ها؛ بودجه بین حرکت‌های ریشه تقسیم می‌شود تا یک شاخه تمام زمان محاسبه را مصرف نکند.
- اتلو: جست‌وجوی عمیق‌تر، جدول موقعیت‌های تکراری، ارزیابی تحرک بالقوه و لبه‌های پایدار؛ در پایان‌بازی کوچک ۸×۸، استادتمام تا حد امکان همه‌ی خانه‌های باقی‌مانده را حل می‌کند و عبور از نوبت را به‌اشتباه یک حرکت مصرف‌کننده‌ی خانه حساب نمی‌کند.
- کریدور: جست‌وجوی پاسخ حریف در سطح‌های بالا و جریمه‌ی بازگشت به خانه‌های اخیر برای جلوگیری از رفت‌وبرگشت بی‌هدف.
- تخته‌نرد: بررسی هر دو ترتیب تاس، ترجیح قطعی توالی‌هایی که از تعداد بیشتری تاس قانونی استفاده می‌کنند، وزن‌دهی برد/باخت قطعی و ارزیابی بهتر تهدیدها و پرایم‌ها. جست‌وجو پس از برد قطعی متوقف می‌شود تا تاس‌های باقی‌مانده حرکت فرضی تولید نکنند. قوانین بار و ورود مجدد همچنان نسخه‌ی ساده‌شده‌ی پروژه هستند.
- گابلت و ابلون: بررسی پاسخ‌های برتر حریف و ادامه‌های کامپیوتر. در گابلت، اگر حرکت ردیف چهار‌تایی حریف را آشکار کند، این باخت بر تکمیل هم‌زمان ردیف خودی اولویت دارد.
- بلاک‌آس: مقایسه‌ی حرکت‌های برتر با بیشترین پاسخ محتمل حریف و تعداد راه‌های ادامه‌ی خودی.
- دومینو، حکم، چهاربرگ و پنتاگو: ارزیابی ادامه‌ی دست/حرکت، نمونه‌گیری از کارت‌های ناشناخته‌ی حکم، سنجش خطر مهره‌ها/کارت‌های در معرض گرفتن و بررسی برد فوری حریف در پنتاگو.
- سطح‌های استاد و استادتمام از تصادفی‌سازی بسیار کمتر استفاده می‌کنند تا تصمیم‌های قوی‌تر و قابل‌تکرارتری بگیرند.
